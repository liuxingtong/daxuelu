# 大学路街道智能体推演

双击 `index.html` 即可运行，所有几何与脚本已内嵌；无需安装、联网或上传模型。当前本机预览：http://127.0.0.1:8792/ 。

## 在飞书文档里运行 / 嵌入

- `index.html` **不依赖 app.js**：`build.py` 会把 model、engine、environment、simulation、app 的代码全部内联进两个 `<script>`，文件里没有任何 `<script src="...">`。把一个 `index.html` 单独复制到空目录，浏览器仍能启动（已验证 24 名行人和 canvas 正常）。
- 飞书个人文档**不会执行上传的 `.html` 附件**；附件预览只显示静态画面，智能体不会跑。这不是 app.js 缺失，而是飞书附件不是 HTML 运行时。
- 「妙笔BOX」HTML 小组件（docx `block_type=40`）和妙搭（Miaoda）应用都属于**企业侧能力**：即使由个人身份创建，发布后的页面域名也会落在企业租户（尝试时是 `tx8wj66o68h.feishu.cn` / `wvixbzgc0u7.feishu.cn`），不是 `my.feishu.cn`。因此它们不适合这个个人文档；相关块、错误附件和链接已从文档末尾移除。
- 个人飞书文档目前**没有可靠的原生 HTML 内嵌方式**。可行方案是把 `index-embed.html` 发布到**公网静态空间**（GitHub Pages、Cloudflare Pages、Vercel、学校/实验室服务器均可），然后在文档里粘贴普通链接；如需在文档里直接看到画面，可同时放一张截图。
- 已打包 `大学路街道智能体-网页版.zip`（含 `index.html` 与 `README.txt`），解压后把整个目录上传到静态空间即可。
- `index-embed.html` 是紧凑网页版：隐藏大页头、导出、设计过程/比较/参数页和页脚；保留地图、行人卡片编辑、热场、社交参数、事件记录和“计算逻辑”弹层。可把文件改名为 `index.html` 后直接上传到任意静态空间。
- `build_feishu_payload.py` 仅保留给**企业租户**中确实支持 `block_type=40` HTML 小组件的文档；个人文档不要用。
- 重新生成：
  ```bash
  python3 build.py          # 完整版 index.html
  python3 build_embed.py    # 紧凑网页版 index-embed.html
  ```
  发布到静态空间时，入口文件名应为 `index.html`。

## 如何看

1. 默认生成 18 名独行者及两组三人结伴者。独行者偶遇可以短暂停留，装置按需求响应。
2. 点行人后，行人附近会弹出可编辑卡片；体表温度、精神状态、步行速度、社交意愿，以及请求休息/停留/恢复/移除都在卡片内完成。点击空白关闭卡片。
3. 切换空气温度、MRT 辐射温度、体感温度或风速图；侧栏可实时改背景气温、来风、观察高度和“社交吸引权重 k_s”。勾选“全圈供热预演”可以假设所有热圈同时供热，查看设计热场；这是预演，不改变智能体调度，但会同步重着色行人体感。右上角“热场详图”把 24×14 m 局部放大，可取消。
4. 在“布局比较与筛选”中，以覆盖和 P95 目标比较索网与热圈数量；可以应用候选布局。“计算逻辑”页集中列出个体、需求、热圈、毛毛虫和环境场的全部公式，包括热圈最近派单、服务区互斥和机体间距规则。
5. 导出平面 PNG 或 JSON 快照；平日模式禁止毛毛虫进入车行道。

## 温度场为什么以前几乎同色

原版不是单纯“热圈发热太少”，而是三个问题叠在一起：

- **空气图选错了量。** 1.8 kW 热光圈以辐射为主，原模型圈心只让空气升约 **0.06℃**，图例却把 6–6.7℃ 映射到整条色带，99% 的格子自然同色。
- **MRT 图色阶过宽。** 热圈正下方 MRT 约 **+4.7℃**，2 m 处约 **+1.8℃**；原图按 **+10℃** 着色，圈心也只走到色带一半，采样还是 1.5 m 网格。
- **很多时刻没有热圈在供热。** 热圈只在 `heating` 状态进入场图；360 秒测试里约 **22%** 的圈-时刻处于供热，其余在沿轨移动或待机，整张图就退回背景值。

现在：空气按 0–1.6 K 的局部混合代理着色；MRT 按 0–4.5 K 着色并改用 1.2 m 网格；新增体感温度场和“全圈供热预演”；图例实时显示峰值和“供热中 n/5”。右上角热场详图放大到 24×14 m。行人圆点按体感温度着色（2–11℃色带），选中后附近弹出参数卡片。

体感温度是未标定的代理：`0.58×空气温度 + 0.42×MRT − 风冷项 + 体表温度/步行速度/精神状态的小偏移`，不是 UTCI 或生理模型。

## 毛毛虫如何协作

需求优先级先考虑休息和照护需求，再考虑人数、寒冷权重和等待。对每个需求，用 0.6 m 网格 A* 求空闲机器人的避障路径，以路径时间选最近可达者。接单后广播需求中心的服务区预留，8 m 内不重复派单；其他机器人服务别处或待机。无人使用且需求散去时释放预留。服务中机器人锁定位置，无人 12 秒后收拢返回。8 m 是可校准的设计假设，当前写在 simulation.mjs 中；尚未实现需求超过单机容量时的多机增援。

## 尺寸依据与设计假设

从原始 3dm 的毫米坐标提取 160 × 60 m 街段，局部原点为原模型 (2000000,310000) mm；主道路宽 12.413 m。建筑、道路、铺装边界来自原模型；设施使用占地近似。树冠包围盒中心作为树干位置代理，不是测绘结果。轨道位置、锚点、装置尺寸、速度、功率和展开包络都是候选设计参数。+X/+Y 是模型轴向，不等同于地理北向。原 3dm 未修改。

轨道总长是候选轨道中心线长度，不是实际索材长度；尚需承载索、支索、锚固、供电、净高和跨索转接设计。几何覆盖不是热舒适保证。静态 P95 仅统计已覆盖采样点从待机位置出发的时间，不含排队、停留识别和现场障碍扰动。有限枚举不是全局最优。

## 参数与环境计算

- 个体输入：体表温度 26–36℃、精神/活动状态、期望速度、社交意愿 S（0–1）；精神状态和社交意愿均为手动/随机情景参数，不推断或诊断醉酒、性格或心理状态。疲惫和酒后状态提高照护优先级并触发休息。
- 寒冷代理 C = clamp((32.5−体表温度)/4 + max(0,12−气温)/16 + 风速/6 − max(0,MRT−气温)/12,0,4)。触发阈值为 max(1,基础停留阈值/(1+0.3C)) 秒。系数均未标定，不是生理舒适指数。
- 建筑背风区域采用指数衰减，局部边缘加速为简化代理；弧幕和膨胀软体按距离/高度减风。未求解流体连续方程、湍流或街谷循环。
- 活跃热圈的功率通过距离衰减估算辐射通量，再按 Stefan–Boltzmann 关系换算等效 MRT。空气温度仅采用小幅混合代理；热源并非把整片空气直接加热到同一温度。
- 供热人数代理 = min(人数上限, floor(功率×有效系数/单人所需功率))；移动/充气/待机暂取 90/140/12 W。压力发光暂以交互状态示意，未模拟膜体变形或击打发电。

这些场只能用于规则探索。下一步把组员输出的风速矢量、空气温度、表面辐射数据按同一坐标导入，替换 environment.mjs；再校准需求模型、功率和人群停留分布。多机器人和多热圈动态避碰仍是示意，不能作为真实机电控制器。

## 社交意愿与吸引

社交意愿 S ∈ [0,1] 同时影响人的停留行为和两套装置的派单：

- 偶遇停留概率：`0.20 × (0.25 + 1.5S̄) × Δt`；停留时长 `10 + 20S̄ + U(0,15)` 秒。
- 独行者选择热点目的地的概率：`0.25 + 0.50S`。
- 群体需求优先级：`100u + max(P_i) + 3n + stay_max/30 + 10k_sS̄`。
- 热圈：社交意愿只进入任务优先级；任务出现后由**最近空闲热圈**响应，不再用社交距离加成。
- 毛毛虫派单成本：`t_R − 10·k_s·S̄`。
- 热圈不重叠：两个热圈的供热服务区中心距必须 ≥ `2×heatRadius`（默认 8 m），否则后一个任务不会派单。
- 热圈机体：中心距 ≥ 3.4 m；任一方移动会侵入该间距时停止让行，避免移动中交叠。
- 毛毛虫额外出动条件：`k_s > 0` 且 `S̄ ≥ 0.80`，因此一个高社交独行者也可能吸引毛毛虫。
- `k_s` 是侧栏“社交吸引权重”滑块（默认 0.60，0–1）。它只改变调度偏好，不改变供热功率或行走速度；k_s=0 时关闭上述社交优先级、毛毛虫派单加成与高社交独行者出动。

吸引是“调度偏好”，不是情感推断：高社交群体的任务会更早进入热圈派单顺序，毛毛虫也会更偏向高社交群体；但热圈仍只选最近空闲者，且不会突破可达半径、服务区互斥或供热容量。

## 三个人深化

A：索网、热光圈、弧幕与覆盖/响应效率。B：软体压缩展开、伸缩底盘、地面可达与协同派单。C：个体差异（体表温度、精神状态、社交意愿）、压力发光、单人/多人交互和 MR 评价。统一使用此米制坐标、需求 ID 和事件日志。
